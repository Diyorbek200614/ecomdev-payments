# Мини-учёт оплат учебного центра

Python 3.10+ (проверено на 3.14) · FastAPI · SQLite · одна HTML-страница без сборки (вариант Б).

- **API** — ученики (CRUD), оплаты (добавление и список по ученику), должники за месяц.
- **Веб-страница** на `/` — список должников за выбранный месяц и форма оплаты, сделана под телефон.
- **Swagger** на `/docs` — все запросы можно попробовать в браузере.
- **23 теста** (pytest) на API.

## Запуск с нуля

Linux / macOS:

```bash
git clone <ссылка на репозиторий> ecomdev-payments
cd ecomdev-payments
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m app.seed                      # необязательно: 5 демо-учеников и оплаты
uvicorn app.main:app --port 8000
```

Windows (PowerShell): то же, но `python -m venv .venv` и `.venv\Scripts\Activate.ps1`.

Открыть http://localhost:8000 (страница) или http://localhost:8000/docs (API).
С телефона в той же сети: `uvicorn app.main:app --host 0.0.0.0 --port 8000` и адрес компьютера.

База — файл `data.sqlite3` в корне проекта, создаётся при первом запуске.
Другой путь: переменная `DB_PATH`.

Тесты:

```bash
pytest -q
```

## API

Суммы — целые числа в сумах (без копеек и float). Даты — `YYYY-MM-DD`.

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/students` | создать ученика `{name, phone, group, monthly_fee}` |
| `GET` | `/students?group=` | список (фильтр по группе необязателен) |
| `GET` | `/students/{id}` | один ученик |
| `PUT` | `/students/{id}` | заменить все поля |
| `PATCH` | `/students/{id}` | изменить часть полей |
| `DELETE` | `/students/{id}` | удалить ученика вместе с его оплатами |
| `POST` | `/payments` | добавить оплату `{student_id, amount, date?}` (дата по умолчанию — сегодня) |
| `GET` | `/students/{id}/payments` | оплаты ученика, новые сверху |
| `GET` | `/debtors?month=YYYY-MM` | должники за месяц (без `month` — текущий) |

Пример:

```bash
curl -X POST localhost:8000/students -H "Content-Type: application/json" \
  -d '{"name":"Азиз Каримов","phone":"+998 90 123-45-67","group":"Python-1","monthly_fee":800000}'
curl -X POST localhost:8000/payments -H "Content-Type: application/json" \
  -d '{"student_id":1,"amount":300000,"date":"2026-10-05"}'
curl "localhost:8000/debtors?month=2026-10"
```

```json
{
  "month": "2026-10",
  "total_debt": 500000,
  "debtors": [
    {"student_id": 1, "name": "Азиз Каримов", "phone": "+998901234567", "group": "Python-1",
     "monthly_fee": 800000, "paid": 300000, "debt": 500000}
  ]
}
```

**Как считается долг.** Для каждого ученика складываются оплаты с датой внутри месяца
(`[1-е число; 1-е число следующего месяца)`). Если сумма меньше `monthly_fee` — ученик
в списке, `debt = monthly_fee − paid`. Сортировка — по долгу, большие сверху.

Проверки: пустое имя/группа, телефон не из 7–15 цифр, сумма ≤ 0, дата оплаты в будущем,
неверный месяц → `422`; несуществующий ученик → `404`. «Сегодня» и «текущий месяц» —
по Ташкенту (UTC+5), а не по часовому поясу сервера.

## Структура

```
app/main.py         маршруты и запрос должников
app/schemas.py      модели запросов/ответов и валидация
app/db.py           SQLite: схема, соединение на запрос
app/seed.py         демо-данные
app/static/index.html   страница для телефона (чистый HTML + JS)
tests/test_api.py   тесты
```

## Что бы улучшил за ещё одну неделю

1. **История тарифа и дата зачисления.** Сейчас долг считается по текущей `monthly_fee`
   и по всем ученикам, даже если ученик пришёл позже: изменил сумму — поменялись и прошлые
   месяцы, новичок становится должником за месяцы до прихода. Нужны таблица
   `fee_history (student_id, fee, valid_from)` и поля `enrolled_on` / `left_on`.
2. **Переплата и долг за прошлые месяцы.** Лишние деньги сейчас не переходят на следующий
   месяц, а долг не накапливается. Сделал бы баланс ученика (начисления минус оплаты)
   и отчёт «общий долг на дату».
3. **Авторизация и журнал.** API открыт всем. Добавил бы вход для администраторов,
   отмену оплаты вместо удаления (с причиной и автором) и мягкое удаление учеников —
   сейчас удаление ученика стирает и его оплаты.
4. **PostgreSQL и миграции.** SQLite хватает для одного центра, но для нескольких
   филиалов и одновременной работы — Postgres + Alembic, пагинация списков.
5. **Telegram-бот (вариант А) поверх того же API** и напоминания должникам по SMS/Telegram,
   плюс деплой в Docker и CI с тестами.
